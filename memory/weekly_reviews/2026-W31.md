## 3. Root Cause — Two Confirmed Infrastructure Failures

This is the real content of the week. Both open threads are now diagnosed.

### 🚨 A. The premarket delay was a TOKEN-BUDGET failure, not a schedule bug.

The launchd schedule is **correct**: `com.benstuart.rocket.premarket` fires at
**4:20 AM MDT = 6:20 AM ET**, three hours before the open.

`~/Library/Logs/RocketTrader/premarket.log` shows what actually happened:

```
🤖 Model: claude-opus-5 (tier: opus)
You've hit your session limit · resets 9am (America/Denver)
⚠️  claude-opus-5 failed (likely rate limit) — retrying with fallback: claude-sonnet-5
You've hit your session limit · resets 9am (America/Denver)
```

The job fired on time, **hit the Claude session limit, and so did the sonnet
fallback.** Analysis did not complete until ~08:05 MDT (10:05 AM ET) — after the
9:45–9:50 ET base window had closed.

**CLAUDE.md already documents this exact failure mode** ("on 2026-07-27 five research
subagents ran on Opus 5, burned 48% of the day's tokens, and starved Rocket's
market_open into a session limit with zero output"). The subagent-overhead rules were
written to prevent it. **It recurred anyway, and this time it cost Rocket the AMCX
entry.** Token budget is not a housekeeping concern — it is now a documented source of
missed trades.

### 🚨 B. The midday routine has never run. Not once.

`com.benstuart.rocket.midday.plist` exists (authored 2026-07-22, scheduled 10:15 MDT /
12:15 ET) but **does not appear in `launchctl list`**, and
`~/Library/Logs/RocketTrader/` contains **no `midday.log` at all.**

The plist was never loaded. Rocket has been running a 4-routine day while believing it
runs 5. Every "check back at midday" plan written in the last 9 days silently never
executed — including the missed-catalyst re-check windows, which are exactly the
mechanism that would have caught AMCX after a late premarket.

**This requires the user to load it — flagged, not self-enabled** (loading it starts an
autonomous agent that places live orders).

### C. Fractional IWM orders — confirmed not supported in code.
`alpaca_client.py:68` — `place_market_order(symbol, qty: int, ...)` sends integer
`qty` only; there is no `notional` path. With IWM at ~$291 and Rocket's slice at
~$3,040, **one share = 9.6% of the slice vs a 3% rebalance band** — the band cannot be
satisfied by any whole-share move. This mechanically generated a band breach and a
correcting trade on 7/28, 7/30 **and** 7/31. It is a code fix, not a judgment call.
